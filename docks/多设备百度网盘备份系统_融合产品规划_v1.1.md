# 01  产品定位与范围

*第一部分｜产品主文档*

## 一句话定义

一款在多台电脑上运行、以百度网盘为首个远端目标的**版本化备份管理客户端**：识别重复内容，复用兼容备份，保留设备路径与历史，显示可解释状态，并支持可验证恢复。

## 原始需求追踪

| 编号 | 用户已经明确提出的需求 |
| --- | --- |
| U01 | 多台电脑的大量重复文件和文件夹统一备份到百度网盘 |
| U02 | 已备份内容默认不重复备份 |
| U03 | 显示文件、文件夹状态，支持按状态筛选 |
| U04 | 区分本机、其他设备和已有备份情况 |
| U05 | 直接、加密、压缩、压缩加密四种模式 |
| U06 | 增量备份、多设备协同、断点续传、文件恢复 |
| U07 | 补充遗漏、确定产品细节、形成可交付规划 |

## 建议基线与边界

**目标用户假设：**同一用户或单一所有者的 2—10 台设备，Windows 优先，一个百度网盘账号和一个仓库。不将此假设直接扩展为互不信任的团队多租户系统。容量、文件数和预算未提供。

**共同备份不是双向同步。** A 的修改不覆盖 B 的工作文件；本机删除不立即删除云端历史。同步的是对象索引、快照清单和设备上报信息，不承诺远程实时浏览离线电脑的硬盘。

**默认不重复有范围。** 同仓库、同安全域、策略兼容且已经确认存在的内容不重传文件有效载荷。并发首次上传、网络重试、会话失效可能造成冗余流量；不承诺故障条件下零重复字节。

**首版不做：**自动删除本地重复文件、双向工作文件同步、整机裸机恢复、跨用户无授权去重、默认支持所有运行中数据库、绕过服务商权限或额度。资源管理器扩展、团队角色、多云、多账号和跨平台按后续路线评审。

**成功判定：**正确恢复优先于去重率；在约定验收集内，误判内容相同、虚报已备份、未经授权覆盖和清理误删均为发布阻断项。

# 02  核心概念与业务场景

*内容复用，但路径、策略和历史不能被合并丢失*

## 统一对象模型

| 对象 | 定义与关系 |
| --- | --- |
| 仓库 Repository | 隔离的存储、密钥和格式边界；不默认跨仓库复用 |
| 设备 Device | 稳定身份；名称可改；设备离线不影响已提交数据恢复 |
| 备份计划 BackupPlan | 一台设备上的源范围、规则、模式、调度和保留策略 |
| 文件实例 FileInstance | 设备＋备份根＋相对路径；同内容不同路径是不同实例 |
| 内容 Content | 原始字节及强摘要，不包含唯一原路径的假设 |
| 存储表示 Representation | 同内容在指定压缩、加密、密钥代次和格式下的可恢复表示 |
| 物理对象 Object | 真实上传的数据单元；同一表示允许存在并发生成的候选副本 |
| 快照／清单 Snapshot／Manifest | 某次明确范围内的目录、版本、元数据及错误记录 |

**融合新增：**逻辑查找标识与物理对象 ID 分开。相同内容可以共享一个查找标识，但同时上传生成的密文对象不应因此争用同一可覆盖路径。原始内容摘要也不等于密文摘要。

## 必须成立的典型场景

| 情况 | 用户应看到的行为 |
| --- | --- |
| A 先备份，B 有同内容异名文件 | B 复用内容，提交自己的路径，恢复时保留两边目录 |
| B 仅发现云端候选，尚未登记 | 显示“可复用待登记”，不显示本机路径备份完成 |
| 文件改名／目录整体移动 | 内容不变不重传数据；新旧快照保留各自路径 |
| 文件备份后修改 | 当前版本待备份；历史版本仍可恢复 |
| 两台电脑同时首次上传 | 不互相覆盖；允许可识别暂时冗余，不虚报绝对去重 |
| 外接硬盘断开或权限失效 | 标记离线／不可读，不解释为全盘主动删除 |
| 明文计划改为加密 | 创建满足要求的表示；提示旧明文未自动消失 |
| 云端对象缺失 | 相关路径与历史联动标风险；可恢复范围明确 |
| 旧设备与数据库全部丢失 | 新设备凭云端和恢复材料重建并恢复 |

生命周期：**发现文件 → 确认内容 → 判断策略与复用 → 上传缺失对象 → 提交清单 → 更新保护状态 → 巡检 → 恢复／受控维护。**

# 03  页面、入口与首次使用

*交互规格：可供设计出原型，不冒充已经完成的像素级设计*

## 页面信息架构

| 页面 | 主要展示 | 核心操作 |
| --- | --- | --- |
| P01 总览 | 待保护量、失败、最近完整恢复点、异常与容量 | 处理告警、立即备份、进入恢复 |
| P02 文件浏览器 | 本机树、保护状态、来源、模式、时间和错误 | 筛选、预演、登记复用、版本、恢复 |
| P03 全局重复 | 同内容的设备路径、表示、物理对象与重复原因 | 查看引用、批量登记、导出报告 |
| P04 备份计划 | 范围、排除、四模式、调度、保留 | 创建、扫描预演、修改规则 |
| P05 任务中心 | 扫描／处理／传输／提交／恢复分阶段进度 | 暂停、继续、取消、重试、限速 |
| P06 快照与恢复 | 设备→计划→恢复点→目录树 | 差异比较、恢复预览、恢复验证 |
| P07 仓库与设备 | 授权、密钥、上报时间、异常、维护状态 | 加入／移除、恢复包、健康检查 |
| P08 诊断与设置 | 资源、代理、通知、日志、版本、格式 | 诊断导出、升级、维护预演 |

## 首次配置完整闭环

授权与能力检查 → 创建／加入仓库 → 命名设备 → 配置并验证恢复材料 → 选择目录与模式 → 排除预演 → 扫描与复用分析 → 确认执行 → 提交首个恢复点 → 样本恢复。

扫描预演至少展示：应备份数量与原始大小、预计新增数据、可复用数量、排除与不可读项、超限项、缓存需求。未完整读取内容前，去重、压缩收益和完成时间均标为估计。

## 关键交互规则

**信息层级：**主标签回答“当前观察到的版本是否受保护”；附加标签说明来源、任务和健康。绿色不替代核验时间。点击标签进入“判定依据”，显示快照、对象状态、策略和最后确认时间。

**批量操作：**选中文件夹后必须选择“仅筛选匹配项”或“整个目录”；显示最终作用域和排除项。执行前重新确认规则版本，不能操作被筛选隐藏而未授权的文件。

**关闭窗口：**已启用后台运行时，主窗口关闭保留任务与托盘；用户选择退出服务时先持久化并暂停。仓库锁定、后台服务未运行、设备离线要分别提示。

**空状态：**无备份计划显示配置入口；扫描未完成不显示 100%；远端未同步标为未知；无恢复材料时阻止完成需密钥仓库的首次配置。

# 04  备份状态与判定契约

*一个状态字段不能同时表达内容、任务、设备和健康*

## 独立字段，而不是互斥的“本机／其他设备”枚举

| 维度／字段 | 值或含义 |
| --- | --- |
| 源可见性 source_state | 存在、确认删除、源离线、不可读、未知 |
| 当前保护 protection_state | 未扫描、待识别、未备份、可复用待登记、已备份、已修改、策略不匹配、已排除 |
| 任务 job_state | 空闲、排队、扫描、处理、上传、确认、提交、暂停、失败、取消 |
| 历史与来源 provenance | 历史版本数、本机已登记、引用设备集合、实际上传设备集合 |
| 仓库健康 health_state | 待核验、存在已确认、抽样通过、完整通过、缺失、损坏、暂不可检查 |
| 新鲜度 freshness | 扫描、提交、索引同步、健康检查、完整验证各自的时间 |

“本机已登记”和“其他设备已登记”可以同时为真。上传来源是数据对象的来源；块级实现后，一个文件可能对应多个上传设备。凭据过期或密钥锁定不等于已经证明对象损坏，应显示访问受阻。

## 当前版本“已备份”的全部条件

本次确认的内容与受保护元数据匹配；本机路径存在于已提交快照；依赖对象均已确认或可可靠复用；实际存储策略符合要求；没有已知缺失、损坏或无法解析的依赖。

这个结论只针对**最后观察到的源版本**。若源状态或远端检查过期，显示“截至某时”；监听事件使当前判断失效并重新排队。界面不能把离线缓存描述为实时保证。

## 状态变化示例

| 事件 | 主状态与附加说明 |
| --- | --- |
| 发现其他设备兼容对象，但尚未提交本机路径 | 可复用待登记；其他设备已有内容 |
| 本机引用登记成功 | 已备份；本机已登记；内容由 A 上传 |
| 上传完成但清单未提交 | 提交中；尚未形成该路径恢复点 |
| 已备份文件再次改变 | 已修改；有历史版本；新版本待备份 |
| 对象被确认缺失 | 存在风险；影响范围与最后可恢复版本可见 |
| 任务失败但旧版本仍在 | 当前未完成；历史仍可恢复；显示具体错误 |

展示优先级：已知恢复风险优先警示，其次是源未知／不可读，再显示当前保护结论；任务失败不能抹掉已有历史事实，历史存在也不能掩盖当前版本未保护。

# 04  文件夹、筛选与重复视图

*状态模型续：把“能筛选”落实成明确集合与操作范围*

## 文件夹聚合规则

设 N 为当前已完成扫描范围内应备份文件实例数，P 为其中当前版本已保护数。显示文件覆盖 P/N，同时显示已保护字节／应保护字节、排除数、不可读数和未知数。空目录与所选目录元数据单独核对。

全部已备份必须满足：范围完整、N=P、目录结构及空目录已提交、无阻断项。N=0 时，真正空且已提交显示“空目录已备份”；全部排除显示“无纳入内容”；未扫描或不可读显示“未知”。新增、修改、删除和策略变化使祖先目录重新聚合。

## 筛选逻辑

不同维度之间 AND，同维度多选 OR；支持保存视图。字段包括设备、计划、保护状态、来源、健康、模式、错误、时间、大小、类型、重复情况和历史版本。筛选目录默认保留包含匹配后代的祖先，并显示匹配数量。

| 内置视图 | 精确定义 |
| --- | --- |
| 当前未保护 | 当前存在、未排除，且保护状态不是已备份 |
| 其他设备已有，待登记 | 内容可复用，但本机当前路径未进入有效快照 |
| 本机登记完成 | 当前版本保护成立，且本机路径已登记 |
| 由其他设备上传 | 当前引用对象上传者包含其他设备；不是“本机未备份”的同义词 |
| 有历史、当前已改 | 历史数量大于零，当前保护状态为已修改 |
| 存在风险 | 相关对象缺失／损坏，或必要依赖无法解析 |

## 全局重复视图：正式 V1 必须提供

按原始内容聚合，展开“设备→根目录→路径”。展示原始大小、当前／历史引用数、策略兼容组、物理对象数、最后确认时间与占用口径。索引未同步完整时明确标注观察范围。

**示例：**同一文件有 4 条路径引用，分别采用明文和加密两种策略，云端存在 3 个物理对象。界面解释为“4 条引用、2 组存储表示、1 个额外候选副本”，而不是笼统宣称“只占一份空间”。数量为交互示例。

可批量为本机匹配项登记备份、查看版本、发起修复请求、导出去重报告。不得直接合并路径、静默改变模式或删除本地副本。跨设备重复目录的完整结构比较为 P1；文件内容分组和目录覆盖统计为 P0。

# 05  备份计划与增量版本

*基础变化监听进入首版，历史能力从底层闭环阶段就存在*

## 计划配置与规则

每个计划包含设备、稳定源卷身份、一个或多个根目录、包含／排除规则、处理模式、调度、资源限制和保留策略。子目录可明确覆盖模式；重叠计划必须预演重复扫描、策略冲突和额外表示。

范围规则支持目录、名称、扩展名、大小和用户排除；显示规则命中理由。避免把缓存、恢复暂存与自身仓库再次备份。云端占位文件未取得内容时不能当成已备份；符号链接默认不跟随；Windows 快捷方式作为普通文件，不等同于文件系统链接。

## 三层增量分别定义

| 层次 | 正式 V1／后续规则 |
| --- | --- |
| 扫描增量 | P0：基础监听、去抖、稳定性检查、定时补扫；丢事件、日志溢出、重启后要对账 |
| 文件级增量 | P0：未变不上传；改名仅改路径；内容变化且不可复用时处理整个新文件版本 |
| 块级增量 | P1：只上传变化内容块；大型频繁变更镜像等场景可按 D07 前置 |

上传分片、加密分段、压缩单元都不自动等于块级增量。源大小、时间和文件 ID 是加速线索，不替代首次匹配的完整强摘要；严格扫描提供完整内容复查。

## 快照和删除语义

每个恢复点有明确计划、根、选择范围、规则版本和完整性标记。首次 M1 就实现基础历史版本；后续完善历史浏览，而不是到 V1 才开始保存旧版本。

本地删除仅在源根在线、扫描成功、规则未造成伪缺失时记录。改变排除规则显示“不再纳入”，不立即删除历史。手动备份筛选集仅覆盖选定范围，不能把未选择项标成删除。

部分文件失败时可以提交**部分快照**：成功文件可恢复，失败路径与原因写入清单；不暗中以旧版本填补并宣称本次完整。最近完整成功时间不刷新；重试形成新快照。执行中源又变化，保留实际备份版本，最新版本重新排队。

## 调度建议

手动、固定时段、按间隔、变更后延迟触发均支持；默认开启基础监听更新状态，自动备份按用户选择。错过计划后补跑；提供接电源、计费网络限制、时段限速、缓存配额。睡眠关机期间不承诺运行，显示成功快照时间而非仅显示计划时间。

# 06  四种模式与密钥体验

*数据处理模式、目录呈现和通用归档是三个不同选择*

## 四种数据模式

| 模式 | 处理 | 明确边界 |
| --- | --- | --- |
| 直接／原样 | 原始字节保存 | 不提供文件内容机密性；不等于网盘原目录直读 |
| 压缩 | 对有界单元压缩 | 不提供机密性；需解码；强制与自动压缩分开 |
| 加密 | 认证加密后保存 | 需有效密钥；不承诺网盘原生预览 |
| 压缩加密 | 先压缩，再认证加密 | 保存算法、参数、顺序与密钥代次，支持可验证恢复 |

不默认将整个变化目录每轮重压成巨型归档。自动压缩按收益检测决定是否跳过，显示“评估后未压缩”；强制压缩不得静默改为不压缩。算法从成熟实现中评测选择，暂不将某算法或压缩率承诺为最终结论。

## 策略兼容矩阵

| 已有内容表示 → 本次要求 | 处理 |
| --- | --- |
| 同内容、同仓库、兼容编码和安全域 | 复用完整表示，登记路径 |
| 明文 → 必须加密 | 新建加密表示，提示旧明文仍可能存在 |
| 加密 → 要求普通文件直读 | 不视为等价满足；新建明文须明确隐私提示 |
| 未压缩 → 强制压缩 | 新建压缩表示；自动策略另按规则判断 |
| 不同密钥代次／不同仓库 | 不隐式复用；由经批准兼容或迁移规则处理 |
| 对象未提交／缺失／校验矛盾 | 不能作为可靠复用候选 |

## 仓库与恢复材料的产品规则

**建议基线：**仓库目录清单和全局索引统一加密；四种模式只描述文件数据。因此原样文件的数据对象可为明文，但恢复原目录仍可能需要仓库恢复材料。首次配置必须显示这项区别。明文元数据仓库属于需独立确认的替代配置，不得混淆加密计划的名称隐私承诺。

提供仓库恢复包导出、校验与新设备导入；恢复包放在独立安全位置。数据密钥随机生成，口令用于封装；忘记口令但持有有效恢复材料与全部材料丢失必须分别提示。口令更改、令牌撤销、密钥轮换不是同一个按钮的同一效果。

**D05 必须确认：**是否必须在网盘官方客户端直接看到原目录？是否必须日常使用 ZIP/7z？默认采用专用仓库和独立恢复工具，通用归档作为导出，不承诺二者无代价兼得。

# 07  恢复与健康检查

*先验证，再提交最终文件；恢复报告不能掩盖失败*

## 恢复交互闭环

选择设备、计划和恢复点 → 选择文件／目录 → 检查密钥和对象 → 预演下载量、空间和路径冲突 → 选择目标与策略 → 下载／续传 → 临时解码并校验 → 安全提交目标文件 → 恢复支持的元数据 → 输出报告。

默认恢复到新目录或冲突保留两者。覆盖需要明确授权；执行时目标与预览相比发生变化，暂停该冲突项重新确认。恢复不是镜像同步，不删除目标中原本存在但快照未包含的其他文件。

文件暂存在目标受控位置，验证认证标签、结构、长度和原始内容摘要后再成为最终文件。校验失败只能保留明确标识的受控临时数据或清理临时数据，不能覆盖现有文件，也不能把半成品当作成功。

| 恢复页面字段 | 要求 |
| --- | --- |
| 恢复点 | 时间、设备、计划、完整／部分、验证等级和告警 |
| 预演 | 选中项数、需下载实际对象、缓存与落盘空间、冲突项 |
| 结果 | 成功、跳过、保留两者、失败、元数据未支持分别计数 |
| 报告 | 源路径、目标路径、版本、校验结果和错误；可导出 |

## 健康等级

| 等级 | 完成的工作 | 不代表什么 |
| --- | --- | --- |
| V1 提交确认 | 对象与清单按协议确认 | 未证明全部数据都已下载校验 |
| V2 抽样恢复 | 明确样本范围下载、解码、验证 | 不代表整个仓库全部通过 |
| V3 完整验证 | 对选定快照全部必要数据读取与验证 | 不保证此后永不损坏 |

显示范围与时间；权限失效时显示“暂不可检查”，不直接断言损坏。P0 提供结构／存在性巡检、抽样验证及手动完整验证入口。

## 修复规则

对象缺失时追踪所有受影响引用。其他设备仅在在线、获授权且确认本地内容匹配时参与修复，不能凭旧路径假定文件仍在。若只能重新生成不同密文，则先创建新对象和恢复点，不把旧快照自动改成健康。

原对象编码字节可完整找回时，可按经验证的修复定位记录恢复旧引用；否则历史修复需单独的清单修复协议。高级自动跨设备修复列 P1，首版保证风险可见、手动修复有明确结果。

# 08  异常保护、容量与保留

*保护恢复点，但不把客户端告警包装成不可删除的云端存储*

## 异常保护：正式 V1 的最小闭环

建议监测短时大量修改／删除、批量扩展名变化和备份量突增。阈值应包含最小样本数、绝对数与比例，按计划可调；熵分析等高级检测不是首版必需。外接盘离线和规则调整必须先排除，避免误判。

触发后进入“待确认保护状态”：固定异常前最近恢复点及最近已验证恢复点，暂停清理和迁移；普通新增版本默认仍可保存，但加注“异常期间、未确认”。用户可选择继续、暂停相关计划或认定误报。不要把未验证恢复点称为“健康版本”。

解除保护要展示变更摘要、用户选择和影响范围，写审计记录。没有用户确认不得自动删除保护点。受信任客户端的保护不能阻止拥有云端删除权限的攻击者删除对象，重要资料仍需独立副本。

## 保留策略：有限且有明确分组

建议评审默认值：每设备、每计划和完整范围组保留最近 30 个每日恢复点、12 个每周恢复点、12 个每月恢复点，取并集；每日／周／月各取该时段最后一个成功完整点。无备份的时段不补造恢复点。

锁定点、异常保护点、每组最近一个完整成功点不自动淘汰。部分快照单独管理，不能挤掉最后完整点；手动子集不替代全范围恢复点。日／周／月按计划明确的时区划分；时钟异常先告警并保守保留。规则执行与物理删除分开。

## 容量统计和告警

分开显示逻辑引用量、唯一原始内容量、各策略编码后量、云端实际对象量、元数据量、暂时冗余和实际传输量。历史／多模式／并发副本都占空间，不能把压缩与去重收益重复相加。

容量不足时暂停新上传并解释需求，不自动牺牲最新恢复点。保留已完成对象与断点；缓存不足时安全暂停，不能写满系统盘。恢复任务在资源调度中默认高于后台备份，但允许用户调整且防止低优先任务长期饿死。

**融合新增：**正式 V1 设计受控手动维护入口；只有第 18 章维护门槛通过才开放物理清理。未通过时仅有占用分析和预演，且不能把该版本宣称为已完成长期空间回收验收。

# 09  首版边界与交付路线

*同一套需求编号贯穿原型、研发和测试*

## 版本范围统一

| 阶段 | 核心交付 | 出口条件 |
| --- | --- | --- |
| G0 接入验证 | 自有应用授权、对象上传／下载、断点、路径、配额和一致性 | 核心能力有可追溯实测证据；失败有明确阻断 |

| M2 多设备验证 | 跨设备去重、四模式、状态与重复视图、来源、断点 | 并发及策略切换测试通过；四模式均可恢复 |
| M3 正式 V1 | 基础监听、计划、完整恢复交互、巡检、异常保护、受控维护与安装交付 | 全部 P0 和适用条件项通过，关键决策签核 |

## 正式 V1 的重点

文件与目录状态可解释；全局重复视图可操作；基础变化监听及时使状态失效；四模式与历史恢复完整；任务任意阶段可恢复；恢复材料和云端清单不依赖原电脑；缺失风险可发现；异常保护和安全维护有真实约束。

**长期运行门槛：**需要空间回收的日常场景，必须通过受控维护测试。若尚不能安全停写、对账和回收，可交付容量受限预览版并明确限制，不将删除能力伪装为已交付。

## 不先拍脑袋承诺排期

开发人力、语言、数据规模和应用权限未知，暂不填写固定周数或报价。G0 和 D01—D07 确认后输出工作量区间；以可演示、可测试的出口推进，不用“后续支持”掩盖 P0 缺项。

## 决策记录规范

每项记录选择、确认人、日期、理由、影响的 FR／AT、格式变更和迁移要求。本表目前统一为“待确认”，不是默认签字。

## 条件触发

若要求网盘原目录直读，不能同时默认所有路径只对应一个物理文件；若要求频繁大文件局部修改只传少量数据，块级增量必须前置；若要求严格多租户撤权，共享账号／密钥的基础假设失效；若不能确认全部写入者停写，维护清理保持关闭。

这些变化都需要变更记录，而不是在开发中悄悄降低功能定义。

# 11  架构与实现决策

*第二部分｜技术附录；设计草案，不是经过验证的现有实现*

## 模块与职责

| 模块 | 职责／输出契约 |
| --- | --- |
| UI／Tray | 展示状态、生成有作用域的请求；不自行判断已备份 |
| Background Service | 持久化任务、调度、背压、资源与恢复 |
| Scanner／Watcher | 卷身份、遍历、变更证据、补扫、源版本观察 |
| Hasher／Policy | 强摘要、规则匹配、模式兼容和重复候选 |
| Index／State Query | 合并不可变记录，计算状态与目录聚合；支持分页 |
| Transformer | 有界压缩／认证加密；输出固定编码字节和校验 |
| Storage Adapter | 授权、列表、上传、下载、分片、配额、错误归一 |
| Manifest／Commit | 生成完整引用闭包、快照提交、恢复索引重建 |
| Restore／Verify | 恢复预演、临时解码、内容校验、安全提交与巡检 |
| Security／Maintenance | 密钥、设备注册、审计、停写与清理门槛 |

逻辑链路：**UI → 后台服务／本地状态库 → 扫描与策略 → 处理与传输 → 百度网盘对象与清单**；其他设备读取已发布记录合并本地视图。恢复从清单解析，不依赖扫描原电脑。

## 技术选型的冻结方式

桌面框架、核心语言、压缩算法、数据库具体实现均经过样本验证后冻结。SQLite 可作为来源文档提出的本地事务存储候选；不能把同一个数据库文件放在网盘让多个设备互相覆盖。

先做“复用成熟引擎／自研仓库”的差距评审：四模式、百度适配、逐路径状态、设备来源、稳定续传、格式迁移和独立恢复是否满足。不能因某引擎具有去重能力，就认定它已支持本产品全部要求。

## 待冻结架构决策 ADR

ADR01 客户端栈与后台模型；ADR02 引擎复用边界；ADR03 摘要和编码格式；ADR04 无服务器合并协议；ADR05 密钥封装与元数据隐私；ADR06 有界处理单元；ADR07 安全维护与新设备注册屏障。

每项 ADR 包含备选、取舍、样本实测、失败退路和对应测试。维护与并发方案必须做故障注入，不能只画一个“锁服务”或创建一个锁文件就视为完成。

# 12  本地数据模型

*基础实体：来源表结构与严格业务约束合并*

| 表／实体 | 核心字段 | 约束与用途 |
| --- | --- | --- |
| repositories | repo_id, format, epoch, locator | 隔离命名、安全域和兼容版本 |
| devices | device_id, name, auth_state, seq | 稳定身份；上报时间不等于在线保证 |
| backup_plans | plan_id, device_id, rules_rev, profile | 调度、范围、保留规则版本 |
| source_roots | root_id, plan_id, volume_id, path | 区分盘符变化、离线和真实删除 |
| file_instances | instance_id, root_id, relpath, generation | 保存原名称、源属性和扫描证据 |
| contents | content_id, hash_alg, digest, size | 原始内容；不含唯一设备或路径 |
| profiles | profile_id, codec, crypto, key_epoch | 规范化、不可变的实际编码配置 |
| representations | rep_id, content_id, profile_id | 查找逻辑；仅完整可用表示可复用 |
| objects | object_id, locator, stored_hash, size, uploader | 不可变物理字节；健康与核验时间 |
| representation_chains | chain_id, rep_id, attempt_id, complete | 一个完整候选编码链；不同上传尝试彼此隔离 |
| representation_parts | chain_id, ordinal, object_id, lengths | 固定顺序、边界；支持有界数据单元 |
| snapshots | snapshot_id, plan_id, scope, state, manifest | 完整／部分、提交标识、保护锁 |
| snapshot_entries | snapshot_id, root_id, relpath, kind, rep_id | 路径、元数据、缺失／排除／错误记录 |
| jobs／upload_sessions | job_id, stage, source_gen, resume, cache | 阶段事务、幂等、服务端已确认进度 |
| index_events | device_id, sequence, event_id, previous | 不可变事件、重放去重和缺口检测 |
| verifications | target, level, coverage, result, time | 区分存在性、抽样和完整验证 |
| maintenance_runs | run_id, epoch, registry, acknowledgments | 停写集合、清理预案与审计 |
| audit_events | event_id, actor, action, scope, result | 用户授权、策略和破坏性操作追踪 |

本地敏感字段应受设备凭据和访问控制保护。内容摘要、路径和错误详情不得原样写入不受保护的云端辅助索引或诊断包。

**可重建性：**业务索引从云端清单与已提交记录重建；本地任务断点用于效率，不是唯一恢复依据。尚未提交的源路径不属于灾难恢复承诺。

**融合新增：**不持久化一个万能的 file.state 作为全部真相。状态是源版本、提交事实、策略、健康和时间的派生结果，可缓存但必须标记依据版本与失效条件。

# 12  数据约束与内部接口

*没有约束的字段清单不足以让不同开发者实现一致行为*

## 唯一约束、引用和查询索引

| 规则 | 设计要求 |
| --- | --- |
| 文件路径唯一 | 同 root_id 下的路径键按源文件系统语义生成；保留原名称，不统一粗暴小写 |
| 快照条目唯一 | snapshot_id＋root_id＋path_key；错误条目与成功条目不能相互覆盖成假成功 |
| 内容查找 | 仓库／安全域＋摘要算法＋强摘要＋原始长度；矛盾时隔离核验 |
| 表示查找 | content_id＋规范化实际 profile；不把随机 nonce 当成用户策略字段 |
| 对象身份 | object_id 随机唯一；一个 rep 可有多个完整物理候选，不用唯一远端文件名争抢覆盖 |
| 分段关系 | 单个候选编码链的序号连续、长度和摘要可校验；禁止混拼不同尝试 |
| 事件幂等 | event_id 唯一；device_id＋sequence 唯一；同序号不同内容是冲突不是覆盖 |
| 删除依据 | 引用计数仅作查询缓存；执行删除必须重新验证保留闭包与维护屏障 |

常用查询按设备／计划／保护状态／健康／更新时间建组合索引；大目录分页，聚合按事件增量更新并可全量重建。强摘要变化或策略变化使旧保护缓存失效。

## 内部操作契约

| 操作 | 输入要点 | 返回与安全要求 |
| --- | --- | --- |
| ScanPreview | plan_id, rules_rev, scope | 候选与错误、估算置信范围；不上传 |
| StartBackup | request_id, preview_id, source_scope | job_id；预演过期先重评估 |
| QueryEntries | filter, cursor, observed_version | 条目、多维状态、更新时间；游标范围固定 |
| PrepareRestore | snapshot_id, selection, target, policy | 冲突清单、空间、计划摘要与有效期 |
| ExecuteRestore | request_id, restore_plan, consent | 目标变化时重确认；不能越出授权根 |
| VerifyRepository | scope, level, resource_budget | 范围、结果和受影响引用 |
| PrepareMaintenance | request_id, repo_epoch, scope | 停写状态与只读预案 |
| ExecuteMaintenance | approved_plan, barrier_id | 屏障和计划仍有效才执行；否则拒绝 |

每个写操作记录请求 ID、作用域、规则版本和结果；恢复、清理和策略迁移不与普通备份共用一个含糊“同步”操作。错误同时返回稳定分类码、脱敏说明和可执行下一步。

## 远端结构草案

```text

  registry/<epoch>/<event-id>  # 设备与策略登记记录
```

# 14  备份事务与多设备协议

*安全顺序优先于绝对去重；提交是独立阶段*

## 持久化任务状态机

`QUEUED → SCANNING → IDENTIFYING → PLANNING → ENCODING → UPLOADING → VERIFYING_REMOTE → WRITING_MANIFEST → COMMITTING → COMPLETED/PARTIAL`

任意可中断阶段可转 PAUSED／RETRY_WAIT／FAILED／CANCELLED；恢复必须根据持久化证据进入合法阶段，不凭进度百分比直接跳到成功。

| 阶段 | 必须持久化／检查 | 崩溃后行为 |
| --- | --- | --- |
| 扫描与识别 | scope、rules_rev、source_generation、摘要 | 源变则重新排队；不能沿用过期当前状态 |
| 编码与上传 | 实际 profile、缓存摘要、对象 ID、会话和分片 | 只对同一编码字节续传 |
| 远端确认 | 对象定位、大小、可用校验与确认等级 | 不确定则对账；不标为可复用 |
| 写清单 | 完整可解析引用、部分错误、清单校验 | 清单未完成不发布提交 |
| 提交 | 固定提交 ID、设备序号、清单依赖 | 响应丢失按固定 ID 查询并幂等恢复 |
| 完成本地更新 | 已提交证据与当前 source_generation | 源已变则只登记历史，最新版本仍待备份 |

## 默认无服务器协同

各设备只写自身不可变事件，定期读取并合并。上传前刷新已提交候选，再做策略和健康判断；“正在上传”不是已备份。并发产生完整候选副本时保留双方可恢复引用，后续受控维护再整理。

记录顺序使用设备序号、前置关系和事件标识，不以设备时钟最后者覆盖。发布中预留的序号若被放弃，需有明确中止记录，不能留下无法解释的永久缺口。列表迟延、序号缺口和未知对象进入待确认；重复事件幂等应用。一个设备缺口不应无故阻断其他独立设备完整记录的展示。

## 注册、停写与离线设备

仓库需要可追溯的注册集合；本稿建议由指定管理设备串行签发注册／维护纪元，普通上传不依赖管理设备常在线。管理设备丢失时先停止新注册和清理，经完整恢复及授权重建后再开放。

不能仅靠最后在线时间剔除写入者。离线设备重返必须刷新策略和维护纪元，未提交草稿重新验证对象。无法确认注册集合完整时禁止清理。此管理协议是融合新增设计，须通过第 18 章门槛，不将网盘锁文件视为已解决问题。

# 15  分段、续传与资源控制

*四种粒度分开；文件级增量不承诺大文件局部重传*

## 粒度定义

| 粒度 | 用途 |
| --- | --- |
| 文件内容 | 正式 V1 的跨设备去重与版本识别单位 |
| 内容块 | P1 的文件内部复用单位，用于块级增量 |
| 编码单元 | 压缩／加密／校验和缓存的有界单元；可多个组成一个文件表示 |
| 上传分片 | 服务商要求的传输单位，其规则和会话有效期由 G0 实测 |

原样文件可在限额允许时用一个对象；超限拆分或有界编码会影响原生直读，必须按 D05 已确认体验处理。大文件只改少量内容时，V1 仍可能处理和传输整个新版本；有界编码本身不构成块级增量承诺。

## 源一致性与处理链

先取得稳定读取范围并计算强摘要，再决定复用或编码；若需再次读取，验证读取内容与初始摘要一致，源变化则不提交相互矛盾的版本。普通稳定读取为尽力一致，不等于严格时点的文件系统／应用快照。

需要严格时点一致的应用文件必须使用已验证的快照或应用导出路径；不支持时明确提示。对正在持续写入的文件不能仅凭“能打开”宣布业务一致。

## 断点规则

已编码暂存文件或单元写入有界缓存，保存实际字节摘要。服务端已确认分片为依据，客户端“已发送”不足以跳过；会话有效时可续传，失效时安全新建会话，解释重传范围。

缓存丢失、源改变或参数变化时，废弃不一致的未完成候选，不把新密文拼到旧分片；已完成对象可保留，但只有完整且一致的表示链才能引用。随机数不为新内容重复使用。

取消、掉电和服务重启后保留安全断点。暂时无引用对象进入维护候选，不立即删除。重试有上限、退避和随机抖动；权限、密钥和容量问题转用户操作，不无限重试。

**进度四栏：**已扫描逻辑量、已复用量、真实传输量、待提交量。资源采用有界队列与背压，缓存不足先暂停；加密模式不能静默生成不受控明文暂存。恢复优先但保留公平调度。

# 16  安全与设备生命周期

*密钥、令牌、注册身份分别管理；不承诺无法实现的撤回*

## 加密设计待冻结项

采用成熟认证加密和口令派生库，不自行设计算法。来源方案中的 AEAD、仓库主密钥、分离索引密钥与口令封装可作为候选；具体算法、参数、随机数构造、关联数据和容器格式由安全评审冻结。

去重先查询受保护索引，找到兼容表示直接引用；新对象才生成新密文。禁止固定 nonce 来制造去重，禁止直接以公开内容摘要作为数据密钥。云端查找标识可用仓库范围带密钥摘要，字段采用规范化、带长度的无歧义编码。

对象认证绑定仓库、类型、格式、分段位置和必要长度。文件顺序、结束标记和总长度必须可验证，避免截断和不同对象拼接。仍会暴露对象大小、数量、访问模式及仓库内重复关系，不宣传完全隐藏元信息。

## 设备动作与真实效果

| 动作 | 能达到的效果／限制 |
| --- | --- |
| 移除设备注册 | 停止受信任客户端新任务，保留历史；不自动撤销所有网盘访问 |
| 撤销网盘授权 | 取决于平台实际令牌能力，须实测；不收回已复制文件 |
| 更换解锁口令 | 通常更新密钥封装，不等于重新加密全部历史 |
| 轮换数据密钥 | 新对象用新代次；旧历史保密要另行迁移 |
| 仓库密钥泄露 | 不能靠改密码否认旧密钥有效；制定迁移与数据暴露处置 |
| 设备重装／克隆 | 默认新身份；不能复用旧序号造成覆盖；关联历史需确认 |

## 本地隐私与恢复材料

令牌、主密钥和恢复材料使用系统安全存储与最小权限；不得写入明文日志、普通同步配置、诊断包或崩溃转储。后台自动解锁须用户授权，密钥锁定时需要密钥的任务暂停。

恢复包包含仓库定位、格式、密钥恢复材料和校验说明，不把短期令牌当长期恢复凭据。不仅保存在同一加密仓库内；卸载、系统迁移、口令调整须提示验证恢复材料。

更新机制、发布签名和依赖许可证需纳入交付。重大格式升级先做备份／恢复演练；不承诺所有新格式都可直接回退旧版本，回滚边界需明确。

# 17  恢复安全与异常交互

*恢复路径、目标冲突和特殊文件均是必需业务规则*

## 文件系统支持范围

| 类型 | 正式 V1 的要求 |
| --- | --- |
| 普通文件、空文件、目录、空目录 | 必须正确保存与恢复；有内容摘要／目录完整性依据 |
| 修改时间、基础属性 | 支持项写入矩阵；恢复失败与内容失败分开报告 |
| 创建时间、权限、ACL、所有者 | 按目标系统能力验证；未支持时不能宣传逐属性完整还原 |
| 符号链接、目录连接 | 默认不跟随；支持保存链接则显式校验目标，否则预演标不支持 |
| 硬链接、稀疏文件、备用流、扩展属性 | 样本验证并写支持矩阵；可能膨胀／丢属性必须事前提示 |
| 云端占位文件 | 先取得内容或明确排除，不备份一个占位符冒充原文件 |

所有清单路径视为不可信输入。拒绝目录穿越、越出根的绝对路径、链接跳转、恶意解压输出和不合法名称；处理大小写、Unicode、保留名、同名文件／目录冲突，并给重命名映射。

在目标文件系统的受控临时位置完成校验后提交；提交前重查目标和路径组件，防止预演后目标变更或链接置换导致越界。跨文件系统移动不能假定原子，优先在目标内暂存。

## 错误分类与用户下一步

| 错误码族 | 展示重点 | 默认动作 |
| --- | --- | --- |
| AUTH／KEY | 授权失效与密钥锁定分开 | 保留任务，重授权／解锁 |
| QUOTA／CACHE | 云端不足与本地缓存不足分开 | 暂停相关任务，展示需求与预演 |
| NETWORK／RATE | 断网、超时、限流及下次重试 | 有界自动重试与断点恢复 |
| SOURCE | 源离线、无权限、持续变化、不支持属性 | 不推断删除；定位问题项 |
| INTEGRITY | 对象／清单不匹配、认证失败、缺失 | 阻止成功；隔离并关联影响范围 |
| FORMAT／MAINTENANCE | 版本不兼容、停写屏障、预案过期 | 只读／暂停；不猜测格式继续写 |

通知区分需立即处理、备份延迟、任务摘要；合并重复错误，避免告警风暴。默认不暴露完整敏感路径。诊断导出经用户同意且脱敏，记录事件关联 ID、阶段与版本，不含密钥令牌。

# 18  受控维护与空间回收

*融合新增：提供可实现方向，但以验证门槛而非锁文件作安全证明*

## 维护适用边界

默认面向同一信任域内正确运行的客户端；不把客户端约束当成防恶意写入的服务端隔离。采用指定维护发起者、可追溯注册集合和单调维护纪元；该协议必须评审和故障验证后启用。

## 清理协议草案

| 步骤 | 必须满足的条件 |
| --- | --- |
| 1 冻结注册集合 | 管理端暂停新设备加入和策略迁移；记录完整有效设备集合与纪元 |
| 2 请求停止写入 | 所有登记写入者停止新任务；已在途事务完成或明确中止 |
| 3 持久化确认 | 每台设备先落盘“不可写／未提交任务须重验”，再提交带末序号的停写 ACK |
| 4 完整对账 | 取得所有 ACK；按声明序号读齐提交和依赖，缺口、延迟、未知结果均阻断 |
| 5 生成预案 | 从全部保留快照、保护点和必要清单计算可达闭包，冻结候选对象列表 |
| 6 用户确认 | 显示空间、快照、对象和共享引用影响；确认绑定预案摘要与纪元 |
| 7 执行与校验 | 逐项记录删除结果，可中断重入；先确保保留链完整，不凭过期引用数删除 |
| 8 结束维护 | 发布结果和新纪元；设备刷新后解锁，旧草稿重新查对象再提交 |

## 不能越过的门槛 MG

**MG01** 注册集合可证明完整且无并行注册；**MG02** 所有写入者已持久停写，重启不会绕过；**MG03** 全部提交与引用闭包读齐；**MG04** 预案未过期且用户已确认；**MG05** 崩溃重入不扩大删除范围；**MG06** 恢复检查通过，旧设备重返不会提交失效引用。

任何设备离线未 ACK，就不执行物理删除。不能用“30 天没在线”或用户点击“忽略设备”代替真实停写／撤权证据。无法撤权时可更换隔离仓库继续备份，但不据此清理旧仓库。

## 删除操作的产品边界

日常“移除历史恢复点”先产生逻辑保留变更，不立即删共享对象。“从所有备份永久移除”必须解析所有引用并走维护流程，不承诺服务商历史／回收站安全擦除。

MG 未通过：只显示占用和待清理预演。容量不足则暂停新上传，不自行降低保留策略。正式长期运行验收须验证此闭环，自动周期清理另列 P1。

## 可降级条件

无范围读取时下载完整有界对象再恢复，提前显示流量放大；不能保存物理空对象时用清单记录空文件；上传会话失效可重新传当前未完成对象，不重复已确认的其他对象。

## 不可掩盖的阻断

不能完成完整上传与恢复、无法存储必要清单、授权不适用目标用户群、无法验证安全写入／解析，则核心 G0 不通过。不能静默改用 Cookie、借用凭据或非授权接口来假装达标。

无服务器模式不预设网盘存在可用 CAS、原子锁或强列表一致性。G0 结果若不足以支持默认协议，应调整架构或缩小范围，并重新签核；不以第三方工具能上传作为本应用验证结论。

# 21  质量基线与测试方法

*先定场景和口径，再用实测填入速度、成本和容量*

## 验收环境与数据集

建议基准环境：4 核 CPU、16 GB 内存、SSD、已完成本地索引；真实操作系统、磁盘、网络、应用权限和客户端版本在测试计划中固定。百万级文件记录是验证目标，不是用户已确认规模。

| 数据集 | 覆盖内容 |
| --- | --- |
| T01 基础正确性 | 小文件、空项、同名异内容、异名同内容、改名、时间戳伪保持 |
| T02 规模与介质 | 百万路径、多级目录、大量小文件、媒体、超大文件、外接盘 |
| T03 安全与模式 | 四模式、策略切换、错误密钥、损坏／截断、恶意路径、恢复冲突 |
| T04 并发与故障 | 两设备首次上传、离线／重返、延迟列表、响应丢失、时钟偏差 |
| T05 灾难与维护 | 数据库缓存全损、密钥恢复、停写重启、在途／离线清理阻断 |

人工构造并授权使用测试数据；记录固定输入摘要和预期结果。密码／恢复字段使用测试密钥，不用真实资料做故障注入。

## 正确性与性能目标

所有成功恢复文件强摘要必须一致；错误去重、虚报成功、越界写入、未授权覆盖和清理误删均为零容忍阻断。失败项目显式列出，不能从统计分母中消失。

已索引数据常用筛选 P95 建议不超过 2 秒、首屏不超过 1 秒；空闲内存目标不超过 500 MiB，须固定功能和数据集后评估。以上为建议目标，若不能达到应优化或调整已确认范围，不作现有实测声明。

扫描、摘要、编码、请求数、上传和恢复分别计量；不填写一个跨所有文件类型的虚假吞吐。内存／缓存有界，压力下背压而非无限增长。

## RPO、RTO 与容量

RPO 是可接受的数据丢失时长目标；当前未保护时长根据最后成功且覆盖该范围的恢复点计算，不等于调度间隔。RTO 是目标恢复时限，需用实际下载、解码和落盘耗时验证。重要计划可设置超期告警。

容量模型分别计入当前唯一内容、历史新增、不同模式表示、清单与索引、在途／冗余对象和维护保留。总传输量另含重试，不把网盘内部未知物理去重算成本产品收益。

故障注入覆盖每一持久阶段：杀进程、断网、重启、缓存丢失、令牌失效、对象删除、列表迟延。没有真实平台测试的用例标“待验证”，不能以模拟器通过替代 G0。

| AT40 | 大量改写／删除、误报及解除保护 | 固定保护点、停清理；异常版本加注；解除有审计 |
| AT41 | 日／周／月保留、多设备、长时离线、子集 | 按组取并集；不挤掉最后完整点或保护点 |
| AT42 | 移除／克隆设备、令牌撤销、密钥轮换 | 身份序号不冲突；撤权边界真实；历史迁移独立 |
| AT43 | 占位文件、快捷方式、链接、系统缓存 | 按支持矩阵处理，不把占位／链接误当完整源 |
| AT44 | 统计多模式历史、重试量与超期未备份 | 容量和网络口径分离；告警不泄露敏感详情 |
| AT45 | 缓存耗尽、恢复抢占、后台退出／重启 | 安全暂停、队列有界、可恢复，低优先任务不饿死 |
| AT46 | 有离线未 ACK 设备或在途事务时清理 | MG 不通过，拒绝物理删除；不能靠宽限期绕过 |
| AT47 | 全部 ACK 后校验预案，删除中强制崩溃 | 仅重入同一已确认范围；保留快照依赖不受损 |
| AT48 | 停写后重启旧设备／加入新设备／旧草稿 | 不绕过屏障；维护期间拒绝新写；重返先刷新重验 |
| AT49 | 注册集合不完整、列表缺口或预案过期 | 禁止清理，不降级成猜测引用计数删除 |
| AT50 | 旧客户端读新格式、升级失败、诊断导出 | 只读或拒绝写入；回滚范围明确；无密钥令牌泄露 |
| AT51 | 大文件局部变化／小文件打包（P1） | 按块复用且顺序恢复正确；不以传输分片冒充 CDC |
| AT52 | 运行中业务文件／VSS（条件项） | 在声明支持范围验证一致性；不支持则明确警示 |
| AT53 | 索引压缩／清单修复（P1） | 旧恢复点依赖仍可解，缺失不被加速索引掩盖 |
| AT54 | 接管手工网盘文件／压缩包（P1） | 先只读、确认内容和策略再纳入；不擅自移动删除 |
| AT55 | ZIP/7z／原目录直存（条件项） | 通用工具／原生客户端体验与批准范围一致，边界明示 |

全部适用用例记录 Passed／Failed／Blocked／Not Run。Not Run 不算通过；P0 的 Blocked 或关键安全 Failed 阻断正式发布。性能压力结果另附完整测试报告，不以单次演示代替。

## 每项需求的完成定义

有已批准的语义与界面入口；数据和错误契约明确；单元／集成／适用验收通过；包含重启和失败路径；不会破坏旧版本恢复；文档、诊断和迁移说明随实现更新。

## 整体发布检查

G0 核心链路成立；FR01—FR24 及已前置条件需求通过；AT36 全新设备恢复通过；维护 MG 及适用清理测试通过；安全关键缺陷清零；决策与范围签核；安装、升级、恢复包与独立恢复工具可实际交付。

若维护门槛未满足，只能说明“清理禁用、容量受限预览”，不能把安全删除标完成。若正式 V1 仍缺四模式或历史目录恢复，则不得以 MVP 的演示结果代替需求验收。

# 24  风险、运营与交付包

*产品必须能维护、能解释，也能离开原客户端恢复*

## 风险登记

| 风险 | 影响 | 控制与负责人类别 |
| --- | --- | --- |
| 应用授权／接口不适用 | 核心链路或发布不可用 | G0 前置；平台适配负责人 |
| 去重状态混淆／索引陈旧 | 以为已保护但路径或新版本未备份 | 独立维度与时间；产品＋核心 |
| 并发／停写协议不完整 | 覆盖、坏引用、清理误删 | 唯一对象、MG、故障注入；核心＋测试 |
| 密钥／清单／管理记录丢失 | 有数据却无法恢复或维护 | 恢复包、重建、停清理；安全＋核心 |
| 大文件和海量小文件 | 处理、请求和恢复放大 | D07 样本、粒度评测；性能负责人 |
| 普通文件读取被当成业务一致 | 恢复内容不可用于原应用 | 支持矩阵与条件快照；文件系统负责人 |
| 旧明文残留／共享账号误用 | 隐私承诺不成立 | 明示安全边界和迁移；安全负责人 |
| 长期无安全清理／空间不足 | 新备份停滞 | 提前验证 MG、容量告警；核心＋产品 |
| 范围扩张成同步／清理平台 | 工期扩大、删除风险增加 | 独立立项与变更控制；产品负责人 |

## 研发交付包

已签核 PRD 与变更记录；可点击交互原型；G0 证据；ADR 与数据库约束；仓库格式、Schema 和兼容说明；安装包与后台服务；独立恢复工具及恢复包指南；测试数据、自动化脚本与故障报告；性能／RPO／RTO 实测；升级回滚和维护手册；依赖与许可证清单。

## 运行与支持规则

记录最近扫描、最后完整快照、最近验证与维护状态，失败告警可归并。用户主动导出诊断，不默认上传文件清单。检测到仓库不兼容或损坏时进入安全只读／停止写入，而不是自动修复性覆盖。

容量和变更量定期复核，重要计划做恢复演练。独立恢复工具与格式说明随版本归档；升级后保留恢复兼容证据。产品停止维护时也应能按公开格式／工具导出资料，不把用户数据锁在唯一一份本地数据库里。

## 原有网盘文件接管边界

P1 接管先只读发现，原始摘要和策略不足以确认时需下载验证并展示成本。未确认候选仅标“可能已有副本”。压缩包／加密包不经解析不能认定内部每条路径已被备份；不自动移动、重命名或删除原文件。
